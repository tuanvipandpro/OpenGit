## Ordered implementation

1. Add typed catalog, lazy target, outcome and read-only reconcile APIs. Catalog
   entries have scoped entryId, display ordinal/OID/base and untracked indicator;
   neither displayed OID nor ordinal is renderer authority. Resolve original
   scope/catalog/entry before any authority scope mutation (LIFE01). Bound grant
   to exact object, object format and ordered stack digest. Duplicate OID entries
   remain distinct. Reuse2KiB identity/4KiB grant/16KiB request/8MiB response,
   existing TTL/accounting; no new unbounded registry.
2. Save tracked changes by default; untracked requires explicit opt-in, ignored
   never implicitly included. Native stash push; message only memory/Git, never
   appDB/log. Capture/recheck HEAD/index/config/working/untracked state, journal
   before write. After native quiescence inspect actual objects, stack and working
   state; exit0 or changed tip alone cannot prove app-created stash under a race.
   Git's own stash cleanup is part of Save; no extra app reset/clean/rollback.
3. Apply requires clean tracked baseline and path/casefold/directory/file
   collision checks for existing untracked/ignored data. Reserve durable evidence,
   create refs/opengit/recovery/<owned-token> with expected absence, record exact
   OID ownership, recheck before native resume. Apply pinned OID, never ordinal,
   with -c stash.index=false: restore working changes, not original staged
   partition. Keep stash and pin on conflict/uncertainty. No automatic consume.
4. Pop/Drop fail closed as deferred before write; UI exposes Save/Apply only.
   A static explanation can identify the later version. Do not emulate Pop
   with Apply or introduce a consume strategy now.
5. Minimal conflict flow: detect unmerged stages even without marker files;
   external editor resolution → whole-file Stage → read-only Reconcile.
   In Changes allow whole-file Stage for unmerged paths only when no other busy
   operation. Partial selection stays unsupported; Commit stays blocked while
   any unmerged path remains. Untouched index oracle keys (rawPath,stage), retaining
   other paths' stages1/2/3. Candidate may remain unmerged: no write-tree in that
   case, treeOid null, but same digest/owned-lock/publication proof. No busy-policy
   relaxation for merge/rebase/cherry-pick.
6. Reconcile inspects actual Git and updates evidence; no retry/reset/clean/drop,
   no fake stash Abort, no auto commit. Absence of unmerged paths after a crash
   does not alone prove original Apply succeeded. Preserve historical partial/
   conflict and show resolved externally, stash retained. External conflicts
   without app journal use Changes/Refresh without fabricated operations.
7. UI uses existing interaction lease/Prepare/Execute/stale fences. Save message
   and include-untracked are memory-only, unchecked default. List supports Apply;
   Tasks shows conflicts/recovery and Reconcile. Lost ACK syncs Tasks, never retries.

## Failure/recovery

Use existing bounded optional journal JSON evidence, no SQL migration/dependency:
Reserved → PinCreated → PushStarted/ApplyStarted → Observed/Conflict. Store only
safe OIDs/digests/owned refs/effects; no message/content/runtime grants/raw stderr.
Keep accepted execution ticket/common-dir leases/BQ resources and invalidate
before terminal publication. DB failure before write must leave no native write.
Stack shift must not retarget Apply; entry removal after pin still applies pinned
object. Crash/cancel after start means inspect/unknown, never replay. Native Save
partial cleanup keeps found stash/evidence; no repeat cleanup. New user edits
on restart are preserved. Cleanup only exact owned ref with expected OID and
verified process quiescence; mismatch retains evidence.
