# OpenGit 0.3.0 implementation packets

Approved scope: task007 AC1–AC8, full roadmap0.3.0 plus selected-commit containment/publication evidence. Checkpoint0.2.0 ce5da58 is published on GitHub master; development branch is codex/0.3.0. The user authorizes committing/pushing the0.3.0 branch after checks. No tag/release/installer or0.4 cherry-pick/rebase/merge/full conflict editor is requested. Delivery-order overrides below prioritize usable UI slices; required correctness review remains.

## Shared design and safety contract

- Add typed daily reads and prepare closed ActionIntent → backend plan token → execute → generic operation outcome/reconcile. Renderer supplies bounded new names/messages/options and backend-issued commit/ref/remote/file/hunk/line handles, never argv/path/patch/OID/refspec/config keys.
- Plans bind window/repo/worktree, target identities and preconditions, have explicit TTL/caps, single execution with idempotent repeated submit returning the same operation. Recheck after acquiring common-Git and worktree leases, immediately before write.
- Serialize app writes sharing common Git identity, including worktrees outside app registry discovered by git worktree list. Git native locks plus before/after checks detect external actors; do not promise a universal transaction or rollback against external Git/editors.
- Outcomes: verified applied, verified not applied, conflict, partial, unknown. Cancelled means proven no effects. Push ACK loss, uncertain process quiescence or DB failure after write cannot imply no change. Persist safe intent/phases/pre-post fingerprints/artifact ownership before write; never messages, file contents, credentials, raw URL/stderr. Restart reconciles, never blindly resumes/retries mutations.
- Reuse runner bounded stdin/output, verified owned-job cleanup, AuthSession/helpers, credential safety and history snapshot guards. No dependency changes anticipated. S1 freezes plan/snapshot/handle/resource caps, TTLs and deadlines, bounded by existing16KiB request and8MiB process limits. Over-limit rejects whole request, not silent prefixes.
- Trusted configured Git hooks/clean filters/signers/helpers retain their behavior. No no-verify, signing/TLS/host-check bypass. Errors use structured/static categories; unknown hook/signing cause stays unknown.

## Semantic decisions

**Membership:** resolve selected commit handle to backend OID, inspect every local/remote-tracking branch independently of graph filters/pages. Positive ancestry proves local-ref containment. Negative only when traversal complete; shallow/missing/limits/timeouts have explicit unknown/error, never false definitive absence. Current branch/upstream are separate. Never label absence as never pushed.

**Remote evidence/fetch:** show local tracking snapshot and last app fetch evidence scoped to remote/config/actual observed refs. Endpoint/refspec/config change invalidates fresh interpretation without persisting credential-bearing config. Fetch porcelain verbose can report updated and up-to-date refs; probe installed Git/ref backend support. Narrow refspec and stale deleted refs without prune are mandatory cases. Fetch-all captures remotes and reports per-remote outcomes, including partial failure. Prune always opt-in; suppress implicit prune-tags/submodule recursion. Custom/mirror/refspec affecting local heads/tags requires explicit classification/preview or a clear unsupported result.

**Sync:** explicit source/destination remote ref only, no mirror/all/follow-tags/force push. Remote tag push/delete are distinct actions with safe expected target; never weaken a remote condition silently. FF-only pull fetches upstream, rechecks HEAD/index/worktree/upstream and integrates the pinned fetched OID with FF-only. No autostash, rebase or merge commit.

After acknowledged push, test the captured-endpoint transport's actual local tracking/upstream bookkeeping rather than assuming named-remote behavior. The commit context must reflect verified tracking updates or explicit dated server-ACK evidence; stale local tracking alone must not contradict a known successful push with a definitive not-published label. Any conditional local tracking update needs the same expected-target/journal safeguards and must not overwrite external changes. This belongs to S4/S7 and the final push roundtrip, not an extra S2 feature.

**Staging/commit:** raw-path changes become server handles; backend generates eligible hunk/line patches. Complex binary/rename/mode/filter/encoding cases get whole-file fallback and reason. Use alternate index and expected real-index fingerprint/owned index.lock publication so unrelated stages/working edits survive. Existing runner scrubs GIT_INDEX_FILE; if S5 needs it, introduce an internal typed trusted-index context only, no renderer env. Preserve BQ owned_job. Real Git commit/amend must execute hooks/signing, reconcile actual OID/index and retain effects if write succeeded before later failure.

**Stash:** tracked default, untracked opt-in, no implicit ignored inclusion. Apply/pop require clean tracked baseline and collision checks. Apply pinned object; pop/drop reflog identity is rechecked, ordinal never durable identity. Recovery pins and journal survive apply/consume uncertainty. Git has no stash --abort: conflicted pop retains stash; minimal0.3 flow shows conflicts, external editor resolution, stage and reconcile without auto commit/drop/reset-hard/clean. Startup never auto resumes/consumes.

## Failure gates and unknowns

External HEAD/index/ref/config edits must be rejected before write or reconciled to explicit effects/unknown; no overwrite of unrelated work. Cancel/timeout/crash/DB fault cannot erase evidence or auto retry. Common-directory conflicts serialized. Missing/shallow/caps never trigger implicit fetch/deepen. Prune and remote deletion require explicit intent. Partial index/tree semantics must be proven; unsupported variants get clear supported whole-file fallback. Stash reflog races retain evidence, no atomic rollback promise. Cleanup only exact owned artifacts after verified process quiescence. Migration0–3 preserves data/rolls back.

Hard unknowns to close before exposure: installed Git fetch porcelain/ref backend capability; split/sparse-index and hook behavior under alternate index; reftable/reflog stash consumption races; GUI signer/pinentry behavior; actual writable authenticated native fixture. Unproven capability → NEEDS_REPLAN with reproduction, not weakened checks or false completion.
