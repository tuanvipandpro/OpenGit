## Reproduce checks

From repository root on Windows, with the documented prerequisites installed:

```powershell
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm build
pnpm check:version
. .\scripts\dev-env.ps1
cargo test --manifest-path src-tauri/Cargo.toml --no-default-features --locked --offline
cargo clippy --manifest-path src-tauri/Cargo.toml --no-default-features --locked --offline --all-targets -- -D warnings
cargo fmt --manifest-path src-tauri/Cargo.toml --check
pnpm tauri build --no-bundle -- --locked --offline
```

`scripts/dev-env.ps1` supports the locally provisioned ignored toolchain; standard installed prerequisites may also be used. Cargo offline commands require cached dependencies. Frozen pnpm installation/build passed with the local store and online supply-chain metadata verification; a fully offline pnpm installation is **not proven**. Use the Tauri CLI to produce an executable with embedded frontend assets; a plain Cargo build can compile a binary configured for the development URL.

Native acceptance uses the real Windows Tauri/WebView2 application through tauri-driver/EdgeDriver. Build the opt-in test executable first:

```powershell
pnpm tauri build --no-bundle --features e2e -- --locked --offline
```

Run `tests/e2e/desktop_smoke.py`, `workspace_acceptance.py`, `clone_acceptance.py` and `clone_failures.py` with a Python interpreter and `tests/e2e/requirements.txt` dependencies. The provisioning interpreter also uses ignored `.tools/fixture-python`. Native drivers must match the installed WebView2 runtime. A normal desktop session was required in this environment; the sandbox desktop launch failed. The test feature injects only folder chooser results through process environment. Production builds must omit `e2e` and be checked separately.

## Transport and safety boundaries

Loopback fixtures run real Git HTTPS and SSH servers. Private cases require generated per-run credentials; public cases allow anonymous access. The HTTPS client trusts only the generated fixture CA for these tests, and SSH verifies the generated host key. No certificate verification or SSH trust check is disabled. The fixture agent contains only the generated fixture key and is separately owned; app cancellation must leave it alive. Generated secrets are never printed. Test source repositories and clone targets live under guarded disposable `.tmp` roots.

Native clone acceptance is authored for local/public/private transports, password, host fingerprint confirmation, encrypted key, SSH agent, prompt replay and application-data credential scans. Native failure acceptance is authored for invalid names/sources, existing destination sentinel, waiting cancellation, stale prompt and crash/restart without network resume. All three final R6 native scripts passed: clone success, faults/restart, and workspace. The successful verified-TLS path was rerun with NO_VERIFY absent; the restart baseline was captured before constructing the new process.

Cleanup repair deliberately removes recursive pathname deletion. Verified empty objects may be removed through their own validated handles; nonempty or unproven staging is retained with durable warnings and no automatic recursive deletion on restart. Native assertions distinguish actual removal from safe retention and must never label a retained artifact as removed. The revised pin/re-pin design and deterministic substitution proofs passed independent re-review (G2-R2/R3).

External provider OAuth/GCM browser, enterprise SSO, VPN/proxy policy and provider-specific denied/expired credentials have **no live provider evidence**. Owned loopback results do not prove those integrations. Track them separately from simulated boundary tests and never claim every server policy is supported from these fixtures.

No commit, tag, push, installer publication or release has been performed by this implementation task.

## Test-harness corrections

The historical successful HTTPS GUI run used `GIT_SSL_NO_VERIFY="false"`. Git checks presence rather than parsing a boolean, so that run proves the form/auth/clone/credential-scan behavior but **does not prove certificate verification**. The corrected harness removes the variable before spawning the native process. Both the corrected untrusted-certificate rejection and the successful verified-TLS path passed on the final R6 candidate. Primary source: [Git v2.56 http_init](https://github.com/git/git/blob/v2.56.0/http.c#L1370).

The empty `workspace.owner` file is deliberately locked with sharing disabled. Live scans assert its size is zero and defer reading just that file; closed-process scans read every file. The crash harness selects the unique outermost same-image application below its owned driver (askpass uses the same executable), then verifies the full executable path before terminating it. These are harness corrections, not product acceptance until their full reruns pass.
