## Current source and local evidence

Author v020_backend uses configured worker_complex Sol/high; root owns task007,
plan, this record and tests/e2e. Reviewer v020_reviewer did not author source.
Required findings and exact run snapshots live in
[task007](../tasks/007-implement-0.3.0.md); packet dependencies/failure gates live
in [plan0.3](../plans/0.3.0.md). No token/money cap was set; runtime usage/cost is
unknown. No precise savings are claimed.

The opt-in writable LiveRemotes support and `transport_write_probe.py` use only
owned disposable repositories/servers under `.tmp`. HTTPS uses generated trust
and transient child credentials; SSH uses exact service mappings, pinned host
keys and an owned agent. Synthetic key files follow existing guarded fixture
cleanup. App credentials, system trust and external providers are not modified.
The current probe rejects chunked HTTP and uses bounded small known-length packs;
it does not certify arbitrary pack sizes. Raw local probe log:
`.tmp/0.3.0-transport-write-probe.log`. The independent reviewer also exercised
negative protocol guards. Re-run after relevant fixture changes:

```powershell
. .\scripts\dev-env.ps1
python tests/e2e/transport_write_probe.py
```

S1 preserves legacy clone wire/behavior, adds safe optional action outcomes and
durable phases, and must not mark uncertain writes Cancelled. Recovery is
reconciliation-only, never automatic replay/rollback. Protected preflight reads
must not implicitly fetch missing objects. Older-Git daily capabilities are
probed rather than silently changing the foundation version minimum.

S2 author checks cover local/remote branch containment independently of visible
graph rows, shallow/missing-object unknowns, fetch/prune and multi-remote partial
outcomes, process/DB/cancellation faults, capability probes, ledger limits and
window lifecycle. These are backend checks, not native UI acceptance. The first
parallel fault batch failed because its output-limit case shared a 200 ms timeout;
the test-only deadline correction and focused rerun are recorded in task007.
S2-LIFE02 is independently CLOSED; final-source focused checks and all32 sealed
source/copy hashes passed Gate2a. Broader author142 tests precede the final
per-step digest delta;13lib+3fetch tests cover that delta, as recorded in task007.
Measured debug catalog/prepare/fetch overhead is material; no performance SLA is
claimed and S3 must not introduce an independent catalog polling loop.

External-provider EXT-01 from0.1 remains separate. Successful owned HTTPS/SSH
fixture transport does not close enterprise GCM/OAuth/SSO compatibility.

## Native scenarios awaiting implementation

These are planned checks, not recorded passes. Only the folder chooser may be
injected; Git commands and operation results must come from the application.

1. Open an owned history fixture with a configured local bare remote. Select an
   ancestor whose containing branches differ from its tip decorations; compare
   all qualified local/remote names against Git, including hidden and off-page
   branches. Switch selections/repositories during loading and retain valid diff
   and filter state without showing stale membership as current.
2. Advance the owned remote, fetch through the UI and verify exact ref OIDs,
   dated per-ref evidence and a single coordinated refresh. Exercise stale
   deleted refs with prune disabled, explicit prune, narrowed fetch coverage and
   one successful plus one failed remote. Repeat actual authenticated HTTPS/SSH
   fetch using the owned fixture trust and credentials.
3. Through daily-action UI, create/switch a branch, stage a file and eligible
   partial selection, commit, push a chosen branch and tag, then verify actual
   server refs and preserved unrelated changes. Exercise FF-only pull and
   divergence without choosing an implicit merge/rebase strategy.
4. Stash/apply/pop a disposable conflicting state, resolve externally and stage
   through the app. Restart with interrupted/uncertain evidence and verify no
   automatic mutation replay, stash consumption or cleanup of unrelated edits.
5. Run integrated regression checks, build without the e2e feature, launch that
   production binary and verify usable graph/context/daily controls. Independent
   Gate3 must cover the final files and actual evidence before acceptance.
